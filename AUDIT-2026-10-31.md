- `php -l` **14/14 file PHP**: bersih, tanpa deprekasi.

- Uji fungsional khusus perbaikan v0.5.2 **11/11 PASS** (`scripts/verify-v052.sh`).

### 2.3 Keamanan — solid untuk shared hosting, dengan catatan
✅ Sudah benar: PDO prepared statements di semua query; escaping `e()` (ENT_QUOTES) di semua output — sweep otomatis menemukan **nol** raw-echo; CSRF token `hash_equals` di semua POST; `password_hash`/`password_verify` (bcrypt $2y$12); `session_regenerate_id(true)` saat login; rate limit form kontak 5/menit; blokir akses file sensitif di router php -S **dan** .htaccess; `display_errors=0` di produksi.

⚠️ Ditemukan & **SUDAH DIPERBAIKI di sesi ini (v0.5.2)**:
1. **Bug fungsional**: `article_overrides` hanya ditulis admin, tidak pernah dibaca `render_article()` → edit artikel dari admin tidak berdampak. (Fixed + diuji.)
2. **Form artikel admin tidak memuat nilai override tersimpan** → simpanan kedua menimpa override lama. (Fixed + diuji.)
3. **Brute-force login hanya brake 1 detik per sesi** → bisa dilewati dengan membuang cookie. Kini ditambah rate limit **per IP 5 percobaan/5 menit**. (Fixed + diuji.)
4. **`rate_limited()` memprioritaskan header palsuan `X-Forwarded-For`** → bypass rate limit. Kini `REMOTE_ADDR` diutamakan. (Fixed + diuji.)
5. **Petunjuk password default selalu tampil di halaman login publik**. Kini hanya tampil selama password default masih aktif. (Fixed + diuji.)

⚠️ Masih terbuka (dicatat di rencana kerja):
- SQLite berada di dalam webroot (`data/cms.sqlite`). Terlindungi rewrite `.htaccess` — tapi jika host mengabaikan `.htaccess` (konfigurasi salah AllowOverride / nginx), file DB (hash admin + lead pelanggan) bisa terunduh. Perlu lapis kedua `<FilesMatch>` + pertimbangkan nama file acak saat instalasi.
- Akses langsung `/admin-cms.php` dieksekusi di Apache (mode akses kedua by design) → dua URL untuk panel sama; sebaiknya diblokir agar semua lewat `/admin`.
- Header keamanan belum lengkap: belum ada `X-Frame-Options`/`frame-ancestors`, `HSTS`, `Content-Security-Policy` dasar.
- Belum ada **email/SMTP** sama sekali: pesan kontak hanya masuk SQLite (tak ada notifikasi ke pemilik).
- `search-index.json` & sitemap dibangun ulang tiap request (tanpa file-cache) — masih ringan (2,3 MB data), tapi perlu file-cache sederhana untuk hemat CPU shared hosting.

## 4. KESESUAIAN PHP 8.4

- Baseline terpenuhi: kode lolos `php -l` PHP 8.4.13; memakai fitur modern yang stabil (`strict_types`, typed properties, arrow functions, `match`-free sederhana, named constructor pattern aman, `str_contains`/`str_starts_with`, enum tidak dipakai — tidak diperlukan).

- Tidak ada sintaks >8.4; tidak ada fitur eksperimental.

## 6. RISIKO & DEPENDENSI

| # | Risiko | Dampak | Mitigasi |
|---|---|---|---|
| R1 | `.htaccess` diabaikan host → DB/JSON terunduh | Tinggi (kebocoran data lead + hash) | `<FilesMatch>` deny + uji cPanel + pertimbangkan DB di luar docroot |
| R2 | Seed admin default `admin/bambuwater2025` tidak diganti | Tinggi (ambil alih CMS) | Petunjuk kini hilang pasca-ganti; tambahkan paksa-ganti-password (P1) |
| R3 | lead kontak tidak dinotifikasikan | Sedang (peluang bisnis hilang) | SMTP via PHPMailer + SMTP host cPanel (P0.5) |
| R4 | SEO: URL hash Next.js terindeks sebelumnya | Sedang (duplikasi/404) | Peta redirect 301 hash→clean saat cutover; canonical sudah benar di PHP CMS |
| R5 | `file_get_contents` eksternal (IndexNow) diblokir host | Rendah | Fallback curl (sudah ada di tools), fitur degrade anggun |
| R6 | Token GitHub terekspos di chat | Tinggi (repo) | **Cabut/rotate token segera** (di luar repo) |
